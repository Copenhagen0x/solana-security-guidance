# SOL-029 · Preflight simulation disabled

`skipPreflight: true` (or no `simulateTransaction`) before a mainnet send → reverts are paid, not caught; a live bot desyncs. Fix: keep preflight on, or simulate + assert `err === null`.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the send path with skipPreflight: true (or no simulateTransaction before a mainnet send).

**Do NOT flag when** — cite the number when suppressing a finding:

1. preflight stays on, or simulateTransaction is called and err === null is asserted before the mainnet send
2. skipPreflight: true is on a devnet/test/throwaway path, not a value-moving mainnet send — AND the gate selecting it FAILS CLOSED (defaults to preflight ON for mainnet): an env check like `CLUSTER !== 'mainnet-beta'` that yields skipPreflight when the var is unset does NOT qualify; require an explicit non-mainnet allowlist
