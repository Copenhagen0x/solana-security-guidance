# SOL-019 · Missing discriminator check

Deserialize without the 8-byte Anchor discriminator (`try_deserialize_unchecked`) → wrong-type account of matching length accepted. Fix: `try_deserialize`.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the try_deserialize_unchecked (or manual deserialize) that skips the 8-byte discriminator.

**Do NOT flag when** — cite the number when suppressing a finding:

1. try_deserialize (with the discriminator check) is used, or the 8-byte discriminator is verified manually before the unchecked deserialize
2. the SAME account being deserialized is declared as an Anchor `Account<'info, T>` field (which enforces the discriminator) — not merely that some other account in the same handler is Anchor-typed
