# SOL-005 · Anchor resize without checks

`realloc()` with no owner / size-bound / rent-exemption guard. Fix: verify all three before resizing.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the realloc() call site, and whether owner / size-bound / rent-exemption are checked first.

**Do NOT flag when** — cite the number when suppressing a finding:

1. account.owner == program_id is checked before the realloc
2. the new size is bounded by a validated cap AND rent-exemption is re-funded after the resize
3. the account is newly allocated in THIS instruction AND its size is verified == 0 before the realloc (size==0 is mandatory, not optional; additionally any lamports were transferred by the program, not pre-funded by an attacker), so no attacker-supplied prior state or size can exist
