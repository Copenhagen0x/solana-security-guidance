# SOL-014 · Unchecked integer arithmetic

`+ - *` on ints without `checked_*` → release builds wrap silently, and the wrap IS the bug. Fix: `a.checked_add(b).ok_or(Overflow)?`.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the +/-/* on a balance/counter (attacker-influenced) without checked_*.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the operation already uses checked_/try_/saturating_ math with explicit error handling for the financial case
2. both operands are compile-time-bounded constants that cannot overflow/underflow
3. the value is non-financial AND does not feed any downstream financial calculation (proven by tracing every use-site, not a 'this field looks non-financial' claim), AND the operands are bounded so the maximum possible result cannot exceed the type's max (proven by an explicit checked bound or a type-level guarantee, not an unverified 'validated range')
