# SOL-038 · PDA seed collision

A PDA seed scheme with unpinned element boundaries - a caller-controlled variable-length seed (`String`/`Vec<u8>`/slice) adjacent to another variable element, or two schemes whose fixed prefixes differ in length - lets two DISTINCT logical accounts derive the SAME address (Solana hashes `seeds=[...]` as one flat buffer), so an attacker shifts bytes across a boundary to alias a victim's PDA -> overwrite/spoof/type-confusion. Distinct from SOL-008/016 (which verify a PDA, not the scheme's ambiguity). Fix: fixed-width per-type seed tag from one program-wide enum registry (never per-file constants); hash/length-prefix every variable element, never adjoin two unbounded ones

**Enforcement — review-only.** A judgment-call class with no deterministic pattern: it lives in the standard's review checklist and in your AI agent's [rules file](../../integrations), so the model reviews for it.

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite cite the seeds = [...] expression (in #[account(seeds = ...)] or a find_program_address/create_program_address call) that places a variable-length, caller-influenced element (a String / Vec<u8> / &[u8] / unbounded slice) adjacent to another variable-length element or directly after a non-fixed-width literal, with no fixed-width per-type discriminator separating them — OR a second seed scheme in the same program that ends in a variable element and whose fixed prefix differs in length from a sibling's (so the two flatten to the same bytes) — together with a create/init or address-keyed lookup that trusts the resulting PDA as a unique per-entity address..

**Do NOT flag when** — cite the number when suppressing a finding:

1. The seed array has at most ONE variable-length element and it is the LAST element, every element before it is fixed-width (a fixed-length namespace literal like b"vault", a Pubkey's 32 bytes, a u8/u64::to_le_bytes(), or a [u8; N]) — AND one of the following holds so cross-scheme aliasing is also excluded: (a) this is the program's ONLY PDA scheme that ends in a variable-length element, OR (b) every same-namespace scheme that ends in a variable element carries a fixed-width leading per-type discriminator drawn from one program-wide registry (see exclusion 4), OR (c) all sibling schemes' fixed prefixes are provably equal-length. A single trailing variable prevents only INTRA-scheme byte-shifting; it does NOT prevent two trailing-variable schemes with unequal-length fixed prefixes from aliasing — e.g. [b"a", name] and [b"ab", name2] collide on a|bX == ab|X. Without (a), (b), or (c), do NOT suppress.
2. Every variable-length element is normalized to a FIXED width before being placed in the seeds — hashed to 32 bytes (e.g. hash(name).to_bytes() / keccak), length-prefixed with its own byte count, or truncated/padded to a constant [u8; N] — so element boundaries are unambiguous regardless of content. (Width-fixing alone clears the intra-scheme shift; if more than one record type shares this layout it must ALSO carry the exclusion-4 discriminator, since equal-width-but-untagged schemes still cross-alias.)
3. The seed material is entirely fixed-width or program-controlled (only Pubkeys, fixed integer encodings, enum discriminants, or hardcoded equal-length literals) with NO caller-supplied variable-length bytes, so an attacker cannot shift any boundary or pick a colliding value.
4. Every same-namespace scheme leads with a fixed-width per-type discriminator (seed[0]) drawn from a SINGLE program-wide enum/registry whose variants are guaranteed distinct (e.g. #[repr(u8)] enum PdaTag { ... } used as PdaTag::X as u8, or equal-length distinct type literals controlled in one place) AND no remaining element can byte-shift against the next (each is fixed-width or the variable element is last and width-fixed per exclusion 2). A discriminator that is a free-floating per-file const with no registry does NOT qualify — nothing prevents two account types from sharing the same value and re-colliding.
