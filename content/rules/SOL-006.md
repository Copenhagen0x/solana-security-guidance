# SOL-006 · Missing signer check

Privileged handler mutates state without verifying the signer. Fix: `Signer<>`, or check `is_signer`.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the privileged handler that mutates state without a Signer<> / is_signer check on the caller.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the AccountInfo is a documented `/// CHECK:` used only as a CPI target, program id, or read-only/sysvar ref — not a privileged caller whose signature matters
2. account.is_signer is asserted (or the field is a Signer<>/Account<>) before any state mutation
3. the account is never used to authorize a state change or fund movement — on-chain OR by an off-chain consumer of its emitted/logged key
