# SOL-002 · Cross-market state asymmetry

Counter written by one market and read by another with no per-market scoping → permissionless cross-market inflation drains a shared pool. Fix: gate every write by per-market authorization.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the write site that updates the shared/cross-market counter from a single market's context.

**Do NOT flag when** — cite the number when suppressing a finding:

1. every write to the counter is gated by the market's authority proven via a SIGNATURE — a Signer<> on that authority, a PDA-signed CPI WHERE the signing PDA is derived from seeds sourced from the market account's own on-chain state (its key or a field loaded from it — NOT a caller-supplied market id from instruction data) that bind it to THIS specific market, or has_one/constraint WHERE the bound authority account is itself declared Signer<>; a has_one (or key-equality) on a NON-signing account only checks the key (not consent), and a global/unscoped authority PDA that can sign for ANY market, are NOT sufficient
2. the counter is strictly per-market (not a shared aggregate) and has no cross-market read path

## Real exploits in this class

No publicly catalogued exploit in the [Hacks Database](../../hacks/README.md) maps to this class yet. The rule is drawn from documented Solana audit patterns, not a specific in-the-wild loss.
