# SOL-049 · Struct-padding / non-canonical flag read

A security-relevant byte (an `is_admin`/`is_initialized`/`is_frozen` flag, or alignment/padding) read through a HAND-ROLLED zero-copy reinterpretation - a manual `transmute`, a `*const T` cast over `data.borrow()`, or a hand-written `unsafe impl bytemuck::Pod` - where the byte is attacker-writable and never canonicalized: a `bool` that is any non-zero byte reads true, and padding bytes survive the typed reinterpret. Distinct from SOL-017 (use typed deserialize; this survives a typed zero-copy). Fix: use Anchor `#[account(zero_copy)]` / the real `Pod` derive (never a hand `unsafe impl`); store flags as u8 and assert canonicality on every load and write AND validate the account owner + discriminator (canonicalization alone is bypassable)

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite a hand-rolled zero-copy load site — bytemuck::from_bytes / try_from_bytes / cast_ref over a buffer, a manual transmute or *const T cast over data.borrow(), a hand-written `unsafe impl Pod`, or a raw `[u8; N]` byte indexed directly — where a flag byte is branched on without a canonical-value check OR an alignment/padding byte flows into a hash/equality/serialization, AND a writable code path that lets the attacker set that byte. The safe `#[account(zero_copy)]`+derived-Pod path with a bool field does not compile and is NOT reachable..

**Do NOT flag when** — cite the number when suppressing a finding:

1. the flag is a u8 (not a bool) AND every read path asserts canonicality before use — require!(flag <= 1) (or a match that rejects all bytes except the enumerated valid ones) runs on EVERY load, not only at init — AND the branch tests an exact value (flag == 1), never flag != 0
2. the struct uses Anchor's #[account(zero_copy)] (or derives bytemuck::Pod/Zeroable via the real derive macro — NOT a hand-written `unsafe impl Pod`) on a layout with NO bool fields and NO implicit padding: every byte is a named field, reserved/padding fields included, and those reserved bytes are zero-checked on load — so there is no type-system-skipped byte for an attacker to set and no UB-bool path
3. no padding/reserved byte and no aliased/union field is ever observable: the reinterpreted value is used field-by-field only, and no whole-struct bytes are hashed, equality-compared, serialized, or re-borrowed through an overlapping view (this disqualifies the hand-impl-Pod padding-leak trap that survives a clean u8 flag)
4. the account holding the buffer is provably never attacker-writable for this byte: it is program-owned and only ever written by handlers gated to a signer bound by constraint to a hardcoded/program-stored admin key (a bare Signer<> the caller self-assigns is NOT sufficient), and the buffer is not a caller-supplied AccountInfo reinterpreted with this layout (that is the SOL-017/SOL-007 trap)
5. the value is provably discarded — never used in an authority/state gate, written back, hashed, or emitted (a positive 'not security-relevant' proof, not merely 'this handler does not seem to use it')
