# SOL-001 · Unauthenticated now_slot

Caller-controlled clock into state (pass `u64::MAX`, real cranks then reject as stale → permanent DoS). Fix: authenticate against `Clock::get()?.slot`. *(2 confirmed wins: prog#107, cli#78 F33)*

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the instruction handler that accepts now_slot (or any caller-supplied slot/timestamp) from instruction data.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the caller-supplied slot/timestamp is authenticated against Clock::get()?.slot (e.g. clamped/rejected) before any use
2. the value is provably discarded — never written to an account, emitted in an event, or used in a later gate (a positive 'not persisted' proof, not merely 'this handler does not seem to use it')
3. the handler is gated to an admin that must SIGN AND is bound by an explicit constraint to a hardcoded / program-stored admin key (constraint = signer.key() == config.admin, or has_one = admin WHERE admin is declared Signer<>) — a bare Signer<> with no such binding is a user-supplied key the caller self-assigns and is NOT sufficient, nor is a key-equality/has_one check on a non-signer account — AND the value is never re-read by a permissionless crank or downstream instruction
