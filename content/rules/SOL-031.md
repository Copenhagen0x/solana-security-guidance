# SOL-031 · Stale Jupiter quote

Jupiter quote swapped without a `quoteResponse.contextSlot` freshness check → stale route = worse fill + sandwich/MEV. Fix: refetch/reject when `contextSlot` lags the current slot.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the Jupiter quote consumed (swap built) without a quoteResponse.contextSlot freshness check.

**Do NOT flag when** — cite the number when suppressing a finding:

1. quoteResponse.contextSlot is captured and the route is refetched/rejected when it lags the current slot
2. the quote is consumed within the same slot as the fetch (an undefined 'freshness window' is not sufficient — prefer ex1's explicit contextSlot check) AND a slippage bound protects the fill
