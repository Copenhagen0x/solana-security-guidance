# SOL-025 · Sysvar read by raw deserialize

A sysvar (Clock/Rent) read by **raw-deserializing** account data (`bincode::deserialize::<Clock>`) instead of `Clock::get()` / `Sysvar::from_account_info` (which key-check) → attacker passes a look-alike. Fix: `Clock::get()` / Anchor `Sysvar<>`; never hand-deserialize a sysvar.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the bincode::deserialize of a Clock/Rent sysvar instead of Clock::get() / Sysvar<>.

**Do NOT flag when** — cite the number when suppressing a finding:

1. Clock::get() / Rent::get() or an Anchor Sysvar<> is used (the account key is checked internally)
2. the sysvar account key is explicitly verified against the canonical sysvar id before the raw deserialize
