# SOL-003 · Wrapper re-implements engine

Wrapper redoes engine logic (close/settle/accrue), drifts, skips side-effects. Fix: delegate to the engine; the wrapper only marshals accounts.

**Enforcement — review-only.** A judgment-call class with no deterministic pattern: it lives in the standard's review checklist and in your AI agent's [rules file](../../integrations), so the model reviews for it.

**Value tier — LOW.** LOW — hygiene / defense-in-depth / operational (filtered out by `--min-tier high`)

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the wrapper function that re-implements engine logic instead of delegating to the engine.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the wrapper delegates to the engine (CPI or shared module) and only marshals accounts
2. the duplicated logic is generated from / shares the engine's exact code path AND is covered by a differential test that proves wrapper(x) == engine(x) over the relevant input range (a single happy-path smoke test is NOT sufficient)
