# SOL-028 · Missing slippage / min-out bound

A swap/withdraw/settle derives an output with no caller min-out/max-in → adverse-move/sandwich exposure. Fix: take + enforce a caller bound.

**Enforcement — review-only.** A judgment-call class with no deterministic pattern: it lives in the standard's review checklist and in your AI agent's [rules file](../../integrations), so the model reviews for it.

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the swap/withdraw/settle output derived with no caller min-out / max-in bound.

**Do NOT flag when** — cite the number when suppressing a finding:

1. a caller-supplied min-out / max-in bound is taken and enforced before settlement
2. the output is fixed or oracle-bounded and not subject to an adverse swap/sandwich — and if oracle-bounded, the oracle itself enforces the SOL-024 staleness + confidence checks for ITS vendor (Pyth, Switchboard, etc.); a silent SOL-024 scanner result does NOT count (the scanner only catches the Pyth surface — verify the actual freshness check exists for whatever oracle is used), since a stale/wide oracle makes 'oracle-bounded' meaningless
