# SOL-035 · Instructions sysvar substitution

Instruction introspection (`load_instruction_at_checked`, `load_current_index_checked`) to confirm a precompile (Ed25519/Secp256k1) signature — on an instructions sysvar passed as a raw `AccountInfo` whose key is never pinned, OR trusting that a precompile ran without checking WHAT it verified → attacker forges the sysvar, or includes a real precompile ix over their own pubkey/message, and spoofs the check. Fix: pin the sysvar (Anchor `Sysvar<Instructions>`, or assert `key == sysvar::instructions::ID`) AND validate the introspected instruction's program id plus its parsed signer pubkey and message against the expected values — confirming only that "a precompile ran" is bypassable with any real signature.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the instruction-introspection call site (load_instruction_at_checked / load_current_index_checked / get_instruction_relative) and the instructions-sysvar account it reads.

**Do NOT flag when** — cite the number when suppressing a finding:

1. BOTH: the account read is an Anchor `Sysvar<'info, Instructions>` (or `account.key() == solana_program::sysvar::instructions::ID` is asserted), AND the introspected precompile instruction's program id, signer pubkey, AND signed message are all validated against the expected values before the result authorizes anything — pinning the sysvar alone is NOT sufficient (a real Ed25519/Secp256k1 ix over an attacker-chosen pubkey/message still passes a 'did a precompile run' check)
2. the introspection result is used only for logging/telemetry — never to authorize a state change, accept a precompile-verified signature, or gate a CPI-origin check (a positive 'not security-relevant' proof, not merely 'looks informational')
