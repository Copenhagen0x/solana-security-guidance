# SOL-016 · Bump seed unvalidated

A stored `.bump` isn't checked against the canonical bump on first read → attacker pre-creates a non-canonical PDA. Fix: compare to the `find_program_address` bump once.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — LOW.** LOW — hygiene / defense-in-depth / operational (filtered out by `--min-tier high`)

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite a stored .bump read OUTSIDE an Anchor bump constraint (e.g. read into a local then passed to create_program_address) with no canonical (find_program_address) compare.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the read is an Anchor constraint reusing a canonical stored bump — `bump = <account>.bump` (or a bare `seeds + bump`) on a typed `Account<'info, T>` whose bump was set at init with a bare canonical `bump` from ctx.bumps: Anchor re-derives the PDA and the typed account enforces owner + discriminator, so confirm the init site stored a canonical bump, then dismiss — this idiomatic reuse is not a finding
2. a non-constraint read is validated against the canonical bump before use (e.g. require!(stored == Pubkey::find_program_address(seeds, program_id).1))
3. the PDA (and its bump) is created in the same instruction using the canonical bump obtained from find_program_address (NOT a caller-supplied bump passed to create_program_address, which accepts any valid off-curve bump and re-introduces the non-canonical-bump bug)
