# SOL-016 · Bump seed unvalidated

A stored `.bump` isn't checked against the canonical bump on first read → attacker pre-creates a non-canonical PDA. Fix: compare to the `find_program_address` bump once.

**Enforcement — machine-checkable.** A deterministic pattern flags this automatically in the [CLI](../../cli), the [GitHub Action](../../action.yml), the [Semgrep ruleset](../../semgrep), the [VS Code extension](../../extensions/vscode), and the [MCP server](../../mcp).

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite a stored .bump whose init-site bump is not provably canonical — reused via `bump = <account>.bump` when init stored a caller-supplied bump, or read into a local and passed to create_program_address, with no find_program_address compare.

**Do NOT flag when** — cite the number when suppressing a finding:

1. the read is `bump = <account>.bump` (or a bare `seeds = [...], bump` with NO `= target` after bump) on a typed `Account<'info, T>`, AND the SAME account's stored bump was written at init by Anchor's bare `bump` / `ctx.bumps.<name>` (canonical) — NOT a caller-supplied `#[instruction(bump)]` value and NOT a value from create_program_address: verify that exact init site, then dismiss (idiomatic canonical reuse, not a finding). If the init bump is caller-supplied or otherwise non-canonical, this reuse IS the bug — keep it (Anchor's `bump = <expr>` re-derives via create_program_address with the GIVEN bump, so a non-canonical stored bump still validates).
2. a non-constraint read is validated against the canonical bump before use (e.g. require!(stored == Pubkey::find_program_address(seeds, program_id).1))
3. the PDA (and its bump) is created in the same instruction using the canonical bump from find_program_address (NOT a caller-supplied bump passed to create_program_address, which accepts any valid off-curve bump and re-introduces the non-canonical-bump bug)
