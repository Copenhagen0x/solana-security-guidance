# SOL-021 · Terminal op gated on a live-only condition

A close/resolve reuses a guard (`status==Fresh`, `expiry>now`) that can't hold once status is **terminal** → reverts forever, funds lock. Fix: a terminal release that ignores freshness/expiry.

**Enforcement — review-only.** A judgment-call class with no deterministic pattern: it lives in the standard's review checklist and in your AI agent's [rules file](../../integrations), so the model reviews for it.

**Value tier — HIGH.** HIGH — high-value; surfaced even at a strict submission floor

**Baseline severity — high.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the close/resolve op guarded by a freshness/expiry condition that cannot hold once status is terminal.

**Do NOT flag when** — cite the number when suppressing a finding:

1. a separate terminal-state release branch exists that ignores the freshness/expiry guard
2. the terminal-state value is unconditionally overwritten on EVERY termination path to a value that IRREVOCABLY satisfies the guard for all future time (e.g. i64::MAX / a permanent terminal flag — a transient value like now + grace_period that lets the guard fail again once the window elapses does NOT qualify), regardless of its prior (possibly attacker-set) value
