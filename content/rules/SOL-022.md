# SOL-022 · Write-only "impaired" counter

A counter bumped when state degrades (valid→impaired), never decremented → funds encumbered forever, slot never reusable. Fix: add the inverse settlement. *(v16 audit F2)*

**Enforcement — review-only.** A judgment-call class with no deterministic pattern: it lives in the standard's review checklist and in your AI agent's [rules file](../../integrations), so the model reviews for it.

**Value tier — LOW.** LOW — hygiene / defense-in-depth / operational (filtered out by `--min-tier high`)

**Baseline severity — medium.** A starting point, not a verdict: calibrate by preconditions × access level (take the lower) per [SEVERITY.md](../../SEVERITY.md).

**Reachability anchor.** To confirm this is exploitable (not merely present), cite the counter incremented when state degrades with no decrement / settlement path.

**Do NOT flag when** — cite the number when suppressing a finding:

1. an inverse decrement / settlement path exists that clears the counter when the state recovers
2. the counter is monotonic AND verified to never gate resource reuse, fund release, OR any fee/penalty calculation (a code-path check tracing every use-site, not a 'by design' comment)
